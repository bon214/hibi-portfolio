# 写真の更新ガイド

このサイトは、月1回程度Codexへ更新を依頼する運用を想定しています。写真と作品データを更新し、ローカルで確認した変更をGitHubへ反映します。公開開始後の反映方法は、サイト完成後に選定する公開方式に合わせて定めます。

## 1. 更新依頼で渡すもの

- 追加・差し替えするWeb掲載用の画像。
- どの写真を残す・外す・差し替えるか。
- 希望する掲載順。ファイル名または既存の固定IDで指定します。
- 代替テキストに必要な、写真に写っている内容。
- 掲載する場合のみ、本人が確認したタイトル・撮影情報・短い言葉。

正式な作品名がない写真に作品名を作る必要はありません。代替テキストは画面を見ることが難しい人へ内容を伝えるための文章であり、作者の意図や写る人物の事情を推測する解説にはしません。

依頼例：

> 添付の3枚を追加し、現在の `hibi-2025-02` を外してください。掲載順は「新しい写真A → hibi-2025-01 → 新しい写真B → 残りの既存作品 → 新しい写真C」にしてください。作品名と撮影地は掲載しません。まずローカルのプレビューで確認します。

## 2. 画像を準備する

1. 本人がWeb掲載を認めた画像と、掲載順を確認します。
2. サイトで表示する軽量画像を `assets/photos/` に置きます。元の縦横比を保ち、未承認の切り取り・色調変更・回転をしません。
3. 書き出した画像そのものの幅・高さを作品データに記録します。原本の寸法をそのまま転記しないでください。
4. 暗部・粒子・色・細部が崩れていないか、実際の表示サイズと拡大表示で比較します。
5. 原本、掲載を承認していない画像、位置情報などの不要な個人情報がGitの対象に混ざっていないか確認します。

現在の5点はローカルのデザイン検証用の参照画像で、正式採用は未確定です。公開前には、採用画像への差し替え・確認と、作品・順序・説明の確認が必要です。原寸参照画像は`assets/reference/`、試作用の軽量コピーは`assets/photos/reference/`に置き、ともにGit管理対象外にします。取得元と利用範囲は [写真の出典と扱い](asset-sources.md) を参照してください。

## 3. 作品データを更新する

`data/works.js` の`works`配列を編集します。表示コードの変更を伴わない写真の追加・並べ替えは、このファイルと画像を中心に行います。作家情報は同ファイルの`artist`にあります。

| 項目 | 扱い |
| --- | --- |
| `id` | 新しい作品には重複しない固定IDを付けます。既存作品の並べ替えでは変更しません |
| `src`・`thumbnail` | 写真全体とサムネイルの、実在する軽量画像パスを指定します |
| `width`・`height` | 表示用ファイルの実際の幅・高さを指定します |
| `alt` | 写っている内容を具体的に記述し、未確認の撮影地・年月・人物の事情を加えません |
| 掲載順 | 作品データの配列順で管理します |
| `title`・`caption` | 本人が確認した情報だけを追加します。未提供の内容は`null`のままにします |
| `selectionStatus` | 現在の試作用参照画像は`reference`です。正式採用時には採用状況に合わせて更新します |

`artist`の`name`、`designation`、`instagram`、`statement`は本人確認に基づいて更新します。正式なステートメントが未提供の場合、`statement`は`null`のままにします。

同じ作品を軽量画像へ差し替える場合は固定IDを保ちます。異なる作品への入れ替えでは新しいIDを使います。URLの `#photo=固定ID` はその作品を指すため、公開後にIDを別作品へ使い回しません。

並べ替える際は、作品のデータ一式を移動します。IDだけ、画像パスだけを交換すると、直接リンクが別の写真を指す原因になります。

## 4. 自動検査する

プロジェクトのディレクトリで実行します。Node.jsが必要ですが、追加パッケージのインストールは不要です。

```sh
node scripts/check-content.mjs
```

固定IDの重複、画像パス、寸法、必須ファイルの問題を解消してから、ブラウザで確認します。この検査の成功だけでは、見た目や操作の確認が完了したことにはなりません。

## 5. ブラウザで確認する

```sh
python3 -m http.server 4186 --bind 127.0.0.1
```

<http://127.0.0.1:4186/> を開き、次を確認します。

- 最初の画面で作品が見え、初期表示の写真が意図したものになっている。
- 掲載順が依頼どおりで、すべての画像が読み込まれる。
- 縦位置・横位置ともに元の構図が見える。暗部・明部・粒子の見え方を確認する。
- 前後の移動、一覧からの選択、拡大の開始と終了、作者紹介の開閉ができる。
- 一覧や拡大を閉じた後、見ていた作品に戻る。
- 各写真のURLを再読み込みしても同じ作品が開く。ブラウザの戻る・進むも確認する。
- キーボードのTab、左右キー、Escapeで必要な操作ができ、閉じた後のフォーカスが分かる。
- スマートフォン相当の縦画面・横画面と大きな画面で、写真全体と操作が見える。
- 作品名・説明・プロフィール・外部リンクに未確認の情報が加わっていない。

確認用のスクリーンショットでは写真の全体、一覧、拡大、スマートフォン表示を残すと、差し替え前後を比較できます。

## 6. GitHubへ反映する

管理先は公開リポジトリ [bon214/hibi-portfolio](https://github.com/bon214/hibi-portfolio) です。更新時には対象の所有者・名称・公開範囲・接続を確認し、ローカル保存とGitHub反映を区別してください。

1. 変更一覧と差分を確認します。
2. 作品データ、必要なコード・更新手順・出典記録・再生成スクリプトを対象にします。現在の原寸参照画像、試作用軽量コピー、QA用スクリーンショット、ローカルの`要件定義.md`は含めません。正式採用画像を追加する場合は、公開リポジトリへの保存を含む許諾範囲を確認します。原本、秘密情報、未承認素材、ローカル検証用ファイルは除きます。
3. 本人確認済みの掲載作品・順序・文章と一致していることを確認します。
4. 写真の追加・削除・並べ替え内容が分かる変更履歴を残し、対象リポジトリへ反映します。
5. GitHub側の変更を確認します。一般公開は、この工程とは別に扱います。

GitHub Actionsの設定、公開サービスへのデプロイ、ドメインやサーバーの契約は、この更新作業には含めません。請求が発生する作業は行いません。

## 7. 戻す場合

変更前の画像と作品データを、Gitの変更履歴から同じ時点に戻します。共有した履歴を強制的に書き換えず、取り消す変更を新しい履歴として残す方法を基本にします。

戻した後も自動検査とブラウザ確認を行います。写真の削除やID変更を含む場合は、その作品への直接リンクがどう表示されるか確認します。公開開始後は、選定した公開手順で反映し、公開URLも確認します。
