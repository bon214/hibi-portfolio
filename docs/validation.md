- `scripts/check-scroll-gestures.mjs`：小さな入力の蓄積、慣性、遷移中入力、逆方向、境界、行・ページ単位、リセットなど13シナリオ合格。

- 390×844のiframeに実アプリを読み込んだTouchEvent結合検査：上・下・斜めから縦は各1枚、タップ・横・ピンチ・中断は0枚。認識したswipeだけtouchendのdefaultが抑止される。これはイベント結合の検査であり、スマートフォン実機の物理操作確認ではない。

ブラウザ任せのSnap選択と移動曲線は実装依存のため、ページ送りの入力判定を明示している。[W3C Scroll Snap](https://www.w3.org/TR/css-scroll-snap-1/#snap-selection)、[W3C Pointer Events](https://www.w3.org/TR/pointerevents3/#determining-supported-direct-manipulation-behavior)を参照。

## 2026-10-29 入力量に同期する追従へ更新

上記の固定440msの自動送りを廃止。操作中の追従と、操作終了後の整列を分けた。一操作で隣の一枚までという範囲は維持している。

- wheelは正規化した累積入力量で追従先を更新し、一つの描画ループで追従する。追加入力のたびに一定時間のアニメーションを再開始しない。
- touchは指の移動量を次のフレームへ反映する。指を保持している間は途中位置とSnap無効状態を維持し、離した時にだけ掲載位置へ収束する。
- 整列は固定時間の補間から、位置と速度を引き継ぐ臨界減衰へ変更。過大なrelease速度を抑え、停止位置を通り越して戻る動きを防ぐ。
- 途中の表示番号と確定URLを分離し、操作終了・中断後の表示位置、番号、URLを揃える。古いwheel timerは操作識別と取消で無効化する。
- 短い縦ドラッグ・元位置へ戻したドラッグは元の写真へ戻り、互換clickによる拡大の誤起動を抑える。横操作や未成立のtouchcancelは自動送りしない。
- 写真の構図・色・掲載順・画像データ・配色・余白は変更していない。

検証結果：

- `npm run check`：従来の入力判定54件に加え、追従・収束の32件が成功。60/120Hzでの整合、途中目標変更、遅いフレーム、1枚の範囲、途中からの再開、小入力、末尾、touch previewを含む。
- 390×844の実アプリを使うイベント結合検査：指を120px動かすと、離す前にscrollYが120px。約6秒保持しても120px・Snap無効を維持し、離した後に次写真の844pxへ整列した。
- 同画面で12pxのwheel入力を30回：約620msの入力中は30.5 / 88.5 / 145 / 206.5 / 267 / 329.5pxと追従し、最終入力から100ms後は358.5px（累積入力量360px）。操作中に全ページ自走せず、操作終了後に844pxへ一枚だけ進んだ。
- 1280×720の通常ブラウザ操作で、小さいホイールの追従後に720pxへ停止し、Snapが復帰することを確認。
- 長い入力でも20枚目を越えず、次の別操作で末尾メニューへ移動。一覧・モノクロ切り替え・拡大表示の開閉後に追従が復帰し、ブラウザの警告・エラーがないことを確認した。スクロールバーやブラウザ由来の位置変更は追従を中断し、古い入力タイマーで引き戻さない。
- 合成TouchEventによる結合検査は、スマートフォン実機の物理操作確認とは区別する。測定記録・スクリーンショットは非公開の`artifacts/`に保存する。
