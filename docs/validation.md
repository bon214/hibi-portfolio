# v1 の確認記録

確認日：2026年10月25日。

以下の公開確認は初回v1の記録。縦スクロールへの変更内容と再確認は末尾に記載。

## 公開前の品質確認

- 写真を一枚ずつ大きく表示。1280 × 720 の画面では横位置写真を約762 × 508で表示し、元の構図を維持。
- 本人作品の一次出典を確認した5点をv1の選定として使用。架空の作品名・シリーズ・撮影情報・作者のステートメントは追加していない。
- 800 / 1400 / 2200px の長辺別WebPとサムネイルを用意。必要な表示サイズに合わせて選択し、拡大時には最大サイズを使用。
- クロップ・色調変更・回転を行わず、原本のICCプロファイルを引き継ぐ。位置情報を含むEXIFは閲覧コピーに含めない。
- 切り替え先の写真を読み込み終えてから表示。連続操作で古い画像と新しい番号が混ざらないよう、非同期処理の結果を照合。
- 管理画面、外部フォント、解析タグ、外部の実行時依存を使用しない。

## 縦スクロールへの更新

トップページを、5点を順に下へスクロールして鑑賞する構成に変更。作品一覧と拡大表示、写真データ・掲載順・画像ファイルは維持。

- 1280 × 720：最初の写真は約762 × 508、スクロール案内の下端は約700px。初画面に写真全体と案内が収まる。
- 390 × 844：横写真350 × 233、縦写真350 × 525を元比率で表示。次の作品が下へ続くことが見える。
- 320 × 568、844 × 390：初回写真と案内が画面内に収まり、横方向のはみ出しなし。
- スクロール時に、写真のフェードと16pxの浮上から通常表示へ戻ることを確認。各写真で一度だけ520ms。最初の写真は待たせず表示する。
- 動きを減らす設定はJavaScript・CSSで判定し、入場効果と滑らかな移動を停止。OS設定を実際に変更しての検証は未実施。
- 一覧からの作品選択、作品URL再読込、一覧のURL再読込からの鑑賞復帰、ブラウザの戻る操作を確認。
- 通常画面の矢印キー移動後にEnterで対象写真を拡大でき、拡大中に別作品へ移動して閉じると該当作品のスクロール位置・フォーカスへ戻る。
- 詳細画像の非同期競合・失敗時の旧作品混在、通常画面のフォーカス、一覧時のスキップリンクをコードレビューし修正。
- `npm run check`、`git diff --check`が成功。公開後は同じ公開検証スクリプトで29ファイルを再照合する。

## 写真ごとに停止するスクロールへの更新

各作品を一画面分の領域に配置し、ブラウザ標準の必須スクロールスナップを設定。写真に揃って停止し、一続きのホイール入力では一枚だけ進む。慣性の末尾と移動中の追加入力を吸収し、次のジェスチャーを待つ。

- 1280 × 720：写真の停止位置は0 / 720 / 1440 / 2160 / 2880px。最初のヘッダーと写真の大きさを維持。
- 大きなホイール入力でも一枚先だけを遷移先とし、移動終了後は記事先頭と画面先頭が一致。
- `scripts/check-scroll-gestures.mjs`：小さな入力の蓄積、慣性、遷移中入力、逆方向、境界、行・ページ単位、リセットなど13シナリオ合格。
- 一覧・ダイアログではスナップとホイール制御を解除。修飾キー付きのズームや横方向の入力も除外。
- 拡大を移動途中で開いて閉じても、該当作品の停止位置に戻る。
- 一覧で選択した作品や直接リンクには、途中の作品で止まらず直接移動する。
- 末尾メニューとフッターまで到達し、上方向の一操作で最後の写真へ戻ることを確認。
- 390 × 844では844px間隔で停止。320 × 568、844 × 390へのサイズ変更でも同じ作品を維持し、横方向のはみ出しなし。
- 元の写真データ・掲載順・画像ファイルは変更しない。新しい実行時モジュールを含め、公開時は30ファイルを照合する。

タッチ端末の実機操作、各種トラックパッド固有の慣性、OSの動きを減らす設定変更は未検証。ブラウザの画面寸法変更とホイール入力、および純粋関数の入力パターン検査を実施する。
